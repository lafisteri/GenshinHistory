# Genshin History

Локальное приложение для сохранения истории экипировки персонажей Genshin Impact по открытой витрине Enka.Network.

## Запуск

Установите Node.js 20.19+ (или 22.12+) и выполните в каталоге проекта:

```bash
npm install
npm run dev
```

Откройте http://localhost:3000, введите UID и нажмите «Обновить витрину». В настройках профиля игры необходимо включить показ характеристик и добавить персонажей в витрину. Запрос выполняется вручную; Enka может возвращать кешированные данные, поэтому повторное обновление доступно после истечения `ttl`.

Для производственной сборки используйте `npm run build`, затем `npm start`. Проверки: `npm test` и `npm run build`.

## Данные

Снимки хранятся в `data/<UID>/<имя персонажа>/<время UTC>.json`, изображения — в `data/images`. Для резервной копии достаточно скопировать каталог `data`. Данные игрока не отправляются никуда, кроме запроса UID к Enka; приложение слушает только localhost. Для просмотра уже сохранённых снимков интернет не требуется. Справочники устанавливаются с приложением, изображения кешируются при получении. Если справочник устарел, неизвестные названия отображаются по ID; обновить его можно обновлением зависимостей и файлов в `reference`.

Состав витрины ограничен тем, что возвращает Enka. Снимок создаётся только при изменении оружия или артефактов; данные персонажа сохраняются в нём для контекста. Ошибка отдельного персонажа не блокирует остальных. Последний повреждённый снимок нужно восстановить или удалить вручную, прежде чем для персонажа можно будет снова сохранять историю.

## Docker и история в Git

Контейнер хранит данные в `./data` и после успешного ручного обновления автоматически коммитит JSON-снимки и отправляет их в ветку `main` репозитория. Используется отдельный служебный клон в Docker volume: ваши локальные изменения кода и индекс Git не затрагиваются. Файлы изображений и `.refresh.json` в Git не отправляются. При удалении снимка удаление также синхронизируется. Ошибки Git отображаются в приложении; снимки при этом остаются на диске.

Для доступа к GitHub нужен токен с правом записи в этот репозиторий. Если вы используете GitHub CLI, сначала выполните `gh auth login`, затем в терминале проекта:

```bash
export GITHUB_TOKEN="$(gh auth token)"
docker compose up -d --build
```

Откройте http://localhost:3000. Контейнер будет перезапускаться автоматически. Токен передаётся через окружение контейнера, поэтому не публикуйте вывод `docker inspect`. Если у вас нет GitHub CLI, можно задать `GITHUB_TOKEN` другим способом перед запуском. Чтобы обновить настройки или токен, повторите команду `docker compose up -d` в терминале с заданным токеном. Для остановки: `docker compose down`.

Для другого адреса, ветки или порта можно задать `GIT_SYNC_REMOTE`, `GIT_SYNC_BRANCH` или `APP_PORT` перед запуском. Git-синхронизация выполняет `fetch` и fast-forward, не перезаписывает изменения удалённой ветки; при конфликте или недоступном GitHub приложение покажет ошибку, а следующая ручная попытка обновления повторит синхронизацию. Для восстановления истории можно скопировать JSON-файлы `data/<UID>` из Git в локальную папку `data`.
